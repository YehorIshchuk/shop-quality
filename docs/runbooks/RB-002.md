# RB-002 · OO-гейт не видав вердикт (алерт A-05 OOGateToolError)

Створено за CAPA-1 після [INC-001](../incidents/INC-001.md). Компонент — legacy `tools/oo_metrics.py`
([документація](../legacy/oo-metrics.md)), рішення — [ADR-0004](../architecture/adr/0004-javalang-java8-syntax-limit.md).

## 1. Тригер

- Алерт **A-05** ([каталог](alerts.md)): у job `oo-gates` крок гейта завершився кодом **3** і анотацією
  `A-05 OOGateToolError`, або `Java syntax guard` — FAIL на `main`.
- Не плутати з кодом **1** `OO GATE: FAIL` — це справжнє порушення порога CBO/LCOM/DIT/NMO, його виправляє автор
  зміни рефакторингом (ЛР8), а не черговий.

## 2. Передумови

Доступ до репозиторію і вкладки Actions; Python ≥ 3.9; `pip install -r tools/requirements.txt`.

## 3. Рівень автоматизації — 2

| Рівень | Що означає | Тут |
|---|---|---|
| 0 | усе вручну | — |
| 1 | скрипти, людина запускає і вирішує | діагностика нижче |
| **2** | **автоматичне виявлення + чітка діагностика, рішення приймає людина** | guard і код 3 самі називають файл і рядок |
| 3 | самовідновлення | не застосовується: переписати код за людину не можна |

## 4. Кроки

1. Відкрити лог job `oo-gates`; знайти рядки `OO TOOL ERROR` або `JAVA SYNTAX GUARD: FAIL` → перелік `file:line`.
2. Відтворити локально:

    ```bash
    python3 tools/java_syntax_guard.py
    ./scripts/oo-gate-god-object.sh check; echo "exit=$?"   # 3 = збій інструмента
    ```

3. Визначити гілку дій:
    - **guard знайшов конструкцію** (record, `case ->`, text block…) → повідомити автора коміту; переписати синтаксисом
      Java 8 за підказкою guard або `git revert <коміт>`. Виняток із ADR-0004 — лише через RFC.
    - **guard чистий, а код 3** → прогалина в guard: додати fixture з цим синтаксисом у `tools/tests/fixtures/`,
      правило в `java_syntax_guard.py`, тест; до виправлення — revert коміту-тригера.
    - **`ModuleNotFoundError` / помилка встановлення** → перевірити `tools/requirements.txt` і кеш pip (дрейф
      залежностей; саме його ловить щотижневий плановий запуск).
4. Не вимикати job (`if: false`) без рішення CCB — це знімає архітектурний захист для всіх змін.

## 5. Верифікація

`python3 -m unittest discover -s tools/tests` → OK; обидва гейти → `OO GATE: PASS`, exit 0; job `oo-gates` і `deploy` — зелені.

## 6. Відкат

`git revert <коміт-тригер>` + push; конвеєр повертається до останнього зеленого стану (≤ 10 хв).

## 7. Ескалація

> 1 год без вердикту у робочий час → L3 (власник legacy-модуля), за [матрицею ескалації](../maintenance-plan.md#3-матриця-ескалації).
Після стабілізації — запис інциденту за шаблоном [INC-001](../incidents/INC-001.md).
