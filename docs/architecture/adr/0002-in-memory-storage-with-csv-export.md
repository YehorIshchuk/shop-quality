# ADR-0002: Сховище даних у пам'яті процесу з експортом замовлень у CSV

- **Номер:** 0002
- **Статус:** Accepted
- **Дата рішення:** 2026-11-15 (зафіксовано заднім числом під час аудиту ЛР10, 2026-11-21: рішення було прийняте
  в ЛР1 неявно, ADR створено вперше; текст відображає стан на момент прийняття і не переписується)
- **Автор / власник:** Yehor Ishchuk
- **Зачеплені документи:** [SDD §4.3, §5](../../sdd.md), [ISD D2, §6](../../isd.md#d2)

## Контекст

Система — навчальне ядро магазину для вимірювання якості коду (SonarQube, CK/MOOD). Потрібно:
детерміновані тести без зовнішнього середовища, запуск однією командою на будь-якій станції,
мінімум залежностей у `pom.xml` (впливає на метрики та час сканування). Реальні користувачі й
дані відсутні; вимоги до збереження даних між запусками немає.

## Розглянуті альтернативи

| # | Варіант | Плюси | Мінуси |
|---|---|---|---|
| A | PostgreSQL у Docker + JPA/Hibernate | реалістично, персистентність, транзакції | Docker на станції недоступний; +2 залежності й ORM-шар; тести потребують БД |
| B | Вбудована H2 (файлова) + JDBC | персистентність без сервера | SQL-схема і міграції заради демо; JDBC-код роздуває метрики |
| C | **Колекції в JVM heap за інтерфейсами-портами + CSV-експорт замовлень** | нуль залежностей, миттєві детерміновані тести, порт дозволяє замінити реалізацію без змін у сервісах | дані втрачаються після завершення процесу; немає конкурентного доступу |

## Рішення

Обрано **C**. `ProductRepository`, `InventoryStore`, `FileOrderRepository`, `SalesLedger` зберігають дані в
`Map` у пам'яті; персистентний артефакт — `FileOrderRepository.exportCsv(Path)` (UTF-8, `;`).
Назва `FileOrderRepository` історична (від CSV-експорту) — клас **не читає** дані з файлу.

## Наслідки

- ✅ Тести виконуються за мілісекунди, збірка не потребує інфраструктури.
- ⚠️ RPO для даних замовлень = весь сеанс процесу (прийнятий ризик, [ISD §6](../../isd.md#d6-backup)).
- ⚠️ Назва `FileOrderRepository` вводить в оману — Javadoc класу уточнено; перейменування запланувати разом із
  заміною реалізації.
- 🔁 Перехід на персистентне сховище оформлюється новим ADR (`0003+`), цей отримує статус `Superseded by ADR-000N`;
  змінюються лише адаптери `infrastructure/` і Composition Root.
